# 苗字ルーツ辞典 ビジュアルリニューアル 設計書

作成日: 2026-08-13

## 1. 目的

公開済みのサイトに世界観を与える。現状は機能的だが視覚的な個性がなく、
「読めるが記憶に残らない」状態にある。

方向性は **現代の和** — 余白と明朝体で構成する、抑制の効いた和。
古文書風の重厚さには寄せない（読みづらくなる）。資料館風の硬さにも寄せない。

## 2. スコープ

### やること

- 配色を藍基調に変更（分布マップの塗り分けを含む）
- Noto Serif JP をビルド時にサブセットして埋め込む
- 苗字の漢字を各詳細ページの主役に据える
- セクション見出しの装飾を和の意匠に変更
- 家紋SVGの導入（Wikimedia Commons から、ライセンス表示付き）
- クレジットページの新設

### やらないこと

- ダークモード（ライト専用の設計を維持する）
- 縦組み（実装コストとアクセシビリティの課題が大きい）
- 家紋の自作（Commons に無い9件は絵を出さない）
- 苗字データの内容変更（別途のファクトチェックで扱う）

## 3. 配色

生成りの地に墨の文字、藍のアクセント。

| 用途 | 現在 | 変更後の方針 |
|---|---|---|
| 背景 | `stone-50` | 生成り（わずかに黄みのある白） |
| 面（カード等） | `white` | 生成りより明るい白 |
| 本文 | `stone-900` | 墨（純黒でなく、わずかに温かみのある濃色） |
| 補助文字 | `stone-600` | 墨の淡い階調 |
| アクセント | `amber-700` | 藍 |
| 罫線 | `stone-200` | 生成りに馴染む淡色 |
| 分布 多い | `#b45309` | 濃藍 |
| 分布 やや多い | `#fbbf24` | 中間の藍 |
| 分布 データなし | `#e7e5e4` | 生成りより少し沈めた色 |

**コントラストは実装時に必ず計算する。** 目標は WCAG AA（4.5:1）以上。
全ペアについて WCAG の相対輝度式で計算した実測値を報告し、下回るものは採用しない。

過去にこのプロジェクトで、地図のラベルがコントラスト2:1のまま
テスト・型チェック・ビルドをすべて通過して公開直前まで到達した実績がある。目視で判断しない。

## 4. 書体

**Noto Serif JP（OFL、無償）をビルド時にサブセットして自己ホストする。**

見出しも本文も明朝で組む。明朝は小サイズで潰れるため、**本文サイズを1段階上げ、行間を広げる**。

### サブセットの自動化

サブセットは「使用する文字が事前に分かる」ことに依存する。手作業で文字集合を作ると、
**苗字を追加した瞬間にその漢字だけ別書体で表示される**事故が起きる。

したがって、ビルド時に以下から使用文字を機械的に収集する。

- `src/data/surnames/*.json` の全文字列フィールド
- `src/lib/prefectures.ts` の47都道府県名
- UI の固定文言

収集した文字集合からサブセットを生成し、**生成されたフォントの cmap を読んで
収集した全文字が含まれることをテストで検証する**。漏れれば CI で落ちる。

サブセット処理には harfbuzz の wasm を使う npm パッケージを用いる。
`fonttools` を要求するツール（glyphhanger 等）は Python 依存になるため、Windows 環境では採用しない。

`font-display: swap` と preload を設定し、読み込み前でも本文が読める状態を保つ。

## 5. 画面

### 苗字詳細ページ

漢字を主役に据える。

1. 漢字を大きく組み、上下に十分な余白を取る
2. 読みは小さく、字間を空けて添える
3. 順位・人口・出典はさらに小さく沈める
4. 本文が始まるまでに「間」を作る

**セクション見出しの罫線を変更する。** 現在の琥珀色の太い縦棒（`border-l-4`）は和の意匠ではない。
見出しの語を左に置き、細い横罫を右へ伸ばす形にする。

### トップページ

検索ボックスに焦点が集まるよう余白を整理する。
「よく調べられる苗字」のカードは漢字を明朝で大きく組む。漢字が並ぶこと自体を意匠とする。

### ランキングページ

罫線を細くし、余白を広げる。
**順位と人口の数字は明朝にしない。** 明朝の数字は桁が揃わず表で読みにくいため、等幅数字を使う。

### ヘッダー・フッター

白いバーをやめ、地の色に溶かして細い罫線だけで区切る。サイト名は明朝の小さなロゴタイプにする。

### クレジットページ（新規）

家紋SVGの出典を記載する。CC BY-SA の表示義務は「どこかに書いてある」では足りず、
利用者がたどれる形である必要がある。フッターからリンクする。

家紋1件ごとに、作者名・ライセンス名・出典URL・改変の有無を記載する。

## 6. 家紋

### 調達方針

**Wikimedia Commons から取得する。** 費用は発生しない。

家紋の意匠そのものは著作権が切れているが、**特定のSVG表現には描いた人の著作権がある**。
画像検索結果からの取得は行わない。

調査結果（`.superpowers/sdd/2026-08-12-surname-roots/kamon-commons-survey.md`）:

- 38件中29件が Commons に存在（実ファイル23点、一部は複数の苗字で共用）
- パブリックドメイン6ファイル、ShareAlike 付き17ファイル
- 作者17名

### ライセンス義務への対応

- **表示（BY）**: クレジットページに作者・ライセンス・出典URL・改変の有無を記載
- **継承（SA）**: 色を変更する場合は改変にあたるため、改変後のSVGを同一ライセンスで配布する旨を明記

### スキーマの拡張

家紋の型を拡張し、**ライセンス情報を必須項目にする**。

```ts
kamon: {
  name: string;
  description: string;
  // 以下、SVGを持つ場合は必須
  svg?: {
    file: string;        // リポジトリ内のパス
    license: string;     // 例: "CC BY-SA 3.0"
    author: string;
    sourceUrl: string;   // Commons のファイルページ
    modified: boolean;   // 色変更等を行ったか
  };
}
```

`svg` を持つなら内側の全項目を必須とする。**出典不明の家紋SVGを追加できない構造にする。**
苗字データで `sources` の空配列を禁止したのと同じ考え方。

### Commons に無い9件

丸に林の字紋（林）、鷹の羽紋・井の字紋（井上）、筌（中島）、撫子（斎藤）、
三つ柏（清水）、丸に笠（高橋）、山口笹紋・山口撫子紋（山口）。

**似た紋での代用は行わない。** 苗字ページに別の家の紋が載るのは、無いより悪い。

文字紋（林・井）やその家に固有の紋（山口笹紋）が Commons に無いのは当然の結果であり、
探し方の問題ではない。

**表示は、紋の位置に破線の枠を置き、図がないことを短く示す。**
他の紋と行の高さが揃い、一覧としての整列が保たれる。
出典・免責・順位の注記と同じく、分かっていないことを隠さない扱いに揃える。

文言は「図案未収録」のような内部事情の言い方を避け、短く中立にする。
将来追加されることを約束する言い方（「準備中」等）もしない。

### 見出し横の紋

**苗字の漢字の横に、大きめの紋を置く。**

紋を持たない苗字（家紋データ自体が無い68件と、図が無い9件）ではここは空になる。
**漢字の位置がずれないこと。** 紋の有無でレイアウトが動くと、ページ間で落ち着きがなくなる。

## 7. リスクと対処

| リスク | 対処 |
|---|---|
| フォント読み込み中に文字が消える | `font-display: swap` と preload |
| 3文字の苗字が375pxで溢れる | 1・2・3文字それぞれで実測。溢れるなら文字数に応じてサイズを変える |
| コントラスト不足 | WCAGの式で全ペアを計算し実測値を報告。4.5:1未満は不可 |
| サブセットのカバー漏れ | cmap を読んで全使用文字を検証するテスト |
| ライセンス表示の漏れ | スキーマで必須化し、テストで検証 |
| 既存80テストの破壊 | 全テスト通過を必須条件とする |

## 8. 検証

- 全テスト・型チェック・lint・ビルドの通過
- 375px / 768px / 1440px での実測（横スクロールの有無、フォントの実効サイズ）
- コントラスト比の実測値の報告
- サブセットフォントのカバー率の検証
- クレジットページに全家紋の出典が出ていることの確認

**描画結果はデプロイするまで誰も見ていない。** 実機で確認してから完了とする。
