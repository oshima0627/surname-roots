> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **ただしデータ作成タスク（Task 2〜11）はサブエージェントへ委譲しないこと。**
> 過去に10件単位を委譲した結果、並列化に逃げて1件も作られない事故が2回起きている。
> コーディネーター自身が1件ずつ fetch して書くこと。

**Goal:** 全国101〜200位の苗字100件を、既存100件と同じ裏取り基準で収録し、検索でヒットするようにする。

**Architecture:** 既存の仕組み（1苗字=1 JSON、ビルド時に全件 zod 検証、静的エクスポート）は変えない。
スキーマの `origin` 下限を60字に下げ、データ品質を守るテストを3本追加してから、10件ずつデータを作る。
画面・検索ロジック・デザインには一切手を入れない。

**Tech Stack:** Next.js 16 静的エクスポート / React 19 / zod / vitest / Cloudflare Workers Static Assets

## Global Constraints

- **記憶で書かない。** 実際に fetch して本文を読んだページだけが情報源。検索スニペットは情報源ではない
- **独立2ソースの一致のみ採用する。** 媒体が違っても署名が同じなら1ソース
- **有名人は1件ずつ本人のページを開いて確認する。** 芸名・旧姓・異体字で外れる例が多発している
- **裏が取れない項目は空にする。** `kamon: []` `famousPeople: []` `rankNational: null` は正当な値
- 対象リストの基準は名字由来net の全国ランキング（<https://myoji-yurai.net/prefectureRanking.htm>）。
  name-power.net は個別の裏取りソースとして使うが、対象集合の基準にはしない
- `origin` は60字以上。60字も書けない苗字は登録せず、その順位を欠番にする
- 日本語URLの疎通確認にシェルの `curl` を使わない。`encodeURI` も使わない。Node の `fetch` を使う
- **既存100件の JSON は1文字も変更しない**
- 家紋画像は Wikimedia Commons のみ。似た紋で代用しない。今回は新規の家紋画像取得を行わない
  （`kamon` は name / description のみ。`svg` フィールドは付けない）
- 都道府県名は `src/lib/prefectures.ts` の47件の正式名称（「東京」であって「東京都」ではない）

### slug の決め方

既存ルール: **最も一般的な字体が素の slug を取り、以降は区別する漢字の音読みを付す**
（既存例: 斎藤=`saito` / 斉藤=`saito-sei`）。

このリストで衝突が確定しているのは次の3件。ここは調査で読みを確認したうえで確定させる。

| 苗字 | 衝突相手 | 採る slug | 理由 |
|---|---|---|---|
| 101 菊地 | 114 菊池 | `kikuchi` | 上位なので素の slug を取る |
| 114 菊池 | 101 菊地 | `kikuchi-chi` | 区別する漢字「池」の音読み「チ」 |
| 188 伊東 | 既存5位 伊藤=`ito` | `ito-to` | 区別する漢字「東」の音読み「トウ」 |

109 渡部 は読みの調査結果で分岐する。

- 「わたべ」が読みとして確認できれば `watabe`（既存6位 渡辺=`watanabe` と衝突しない）
- 「わたなべ」しか確認できなければ `watanabe-bu`（「部」の音読み「ブ」）

大〜で始まる苗字のローマ字は、原則そのまま `o` を使う（`oshima` `otani` `oishi` `omori` `okubo` `ohashi`）。
既存の 71位 大野=`ohno` は 55位 小野=`ono` と衝突したための例外であり、一般則ではない。
**衝突は Task 1 で追加する slug 重複テストが機械的に検出する**ので、手作業で全部照合しなくてよい。
