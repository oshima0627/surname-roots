# 201〜500位の苗字を追加する 実装計画

> **For agentic workers:** 手順は `2026-08-14-rank-101-200.md` と同一。
> **データ作成をサブエージェントへ委譲しないこと。** コーディネーター自身が1件ずつ fetch して書く。

**Goal:** 全国201〜500位の苗字300件を、1〜200位と同じ裏取り基準で収録する。

**Architecture:** 設計書 `2026-08-14-rank-101-200-design.md` をそのまま適用する。
スキーマ・画面・検証テストの変更は不要。**slug 規則だけを拡張する**（後述）。

## Global Constraints

101〜200位のときと同一。要点のみ再掲する。

- **記憶で書かない。** 実際に fetch して本文を読んだページだけが情報源
- **独立2ソース（名字由来net ＋ 日本姓氏語源辞典）の一致のみ採用する**
- **有名人は1件ずつ本人のページを開いて確認する。** 芸名・旧姓・異体字で外れる例が20件以上あった
- **裏が取れない項目は空にする。** `kamon: []` `famousPeople: []` は正当な値
- `origin` は60字以上。書けない苗字は登録せず欠番にし、報告する
- 都道府県分布は名字由来netの**「比率が多い地域 TOP5」**から採る。上位2県が「多い」、3〜5位が「やや多い」
- 新規の家紋画像取得は行わない（`svg` フィールドを付けない）
- **既存200件の JSON は1文字も変更しない**

## slug 規則の拡張（このタスクで必要になった）

## 各バッチの手順

1. `probe.mjs` で10件ぶんの名字由来net・日本姓氏語源辞典を取得する
2. 両ソースの由来を読み、**一致する内容だけ**を60字以上で書く
3. 有名人候補を `person.mjs` で1件ずつ検証する（本名・表記の一致を確認）
4. 比率TOP5 から `多い`（上位2）/`やや多い`（3〜5位）を決める
5. JSONを10件書く
6. `npm test` を通す
7. **ファイル数と1〜500位の欠番を機械的に数えて報告と照合する**
8. コミット

## 完了後（Task Z1: 全体検証）

- `npm test` / `npm run typecheck` / `npm run lint` / `npm run build`
- 詳細ページ数が登録件数と一致することを確認
- **`npm run check:links`**（URLは2000件超になる見込み）
- ブラウザで実表示を確認する。とくに次を見る
  - `/ranking` が500行になってもレイアウトが崩れないか。**500行は1ページとして重すぎないか実測する**
  - 新規の異体字ページ（`saito-itaiji` など）が既存ページと取り違えられていないか
  - 375px 幅で崩れないか
- フォントサブセットの実測サイズを報告する
- README の収録件数・字体違い一覧・既知の限界を更新する
- main へマージして `npm run deploy`
