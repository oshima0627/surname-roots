# 501〜1000位の苗字を追加する 実装計画

> **For agentic workers:** 手順は `2026-08-14-rank-201-500.md` と同一。
> **データ作成をサブエージェントへ委譲しないこと。** コーディネーター自身が1件ずつ fetch して書く。

**Goal:** 全国501〜1000位の苗字500件を、1〜500位と同じ裏取り基準で収録し、合計1000件にする。

**Architecture:** 設計書 `2026-08-14-rank-101-200-design.md` をそのまま適用する。
スキーマ・画面・検証テストの変更は不要。**slug 規則だけをさらに拡張する**（後述）。

## Global Constraints

既存と同一。要点のみ再掲する。

- **記憶で書かない。** 実際に fetch して本文を読んだページだけが情報源
- **独立2ソース（名字由来net ＋ 日本姓氏語源辞典）の一致のみ採用する**
- **有名人は1件ずつ本人のページを開いて確認する。** 芸名・旧姓・異体字で外れる例が30件以上あった
- **裏が取れない項目は空にする。** `kamon: []` `famousPeople: []` は正当な値
- `origin` は60字以上。書けない苗字は登録せず欠番にし、報告する
- 都道府県分布は名字由来netの**「比率が多い地域 TOP5」**から採る。上位2県が「多い」、3〜5位が「やや多い」
- 新規の家紋画像取得は行わない（`svg` フィールドを付けない）
- **既存500件の JSON は1文字も変更しない**

## slug 規則の再拡張（このタスクで必要になった）

既存ルール:

1. 最も一般的な字体が素の slug を取る（順位が上のほう）
2. 以降は**区別する漢字の音読み**を付す（荒井 `arai-ko`）
3. 音読みが元の字と同じ異体字・旧字体は `-itaiji`（齋藤 `saito-itaiji`）

501〜1000位では、**同じ素の字に対して異体字が2つ目に現れる**組がある（渡辺→渡邊→渡邉）。
ルール3では2つ目を表現できない。そこで次を追加する。

> **同じ素の字に対する2つ目以降の異体字は、順位順に `-itaiji2`, `-itaiji3` … と付す。**

また、**単漢字の苗字が既存 slug と衝突する場合**は、ルール2をその1字に適用する
（沖「おき」は大木 `oki` と衝突するので `oki-chu`）。

## 各バッチの手順

1. `probe.mjs` で10件ぶんの名字由来net・日本姓氏語源辞典を取得する
2. 両ソースの由来を読み、**一致する内容だけ**を60字以上で書く
3. 有名人候補を `person.mjs` で1件ずつ検証する（本名・表記の一致を確認）
4. 比率TOP5 から `多い`（上位2）/`やや多い`（3〜5位）を決める
5. JSONを10件書く
6. `npm test` を通す
7. **ファイル数と1〜1000位の欠番を機械的に数えて報告と照合する**
8. コミット

## 完了後（Task Z1: 全体検証）

- `npm test` / `npm run typecheck` / `npm run lint` / `npm run build`
- 詳細ページ数が登録件数と一致することを確認
- **`npm run check:links`**（URLは3000件超になる見込み）
- **`/ranking` が1000行になったときの実測。** 500行で問題なかったからといって1000行が
  問題ないとは限らない。HTML実バイト数を測り、重すぎるなら分割か遅延描画を検討する
- 新規の異体字ページが既存ページと取り違えられていないかを `out/myoji/<slug>.html` の
  `<title>` で機械的に照合する（**フラット出力。`<slug>/index.html` ではない**）
- 375px 幅で崩れないか
- フォントサブセットの実測サイズを報告する
- README の収録件数・字体違い一覧・既知の限界を更新する
- main へマージして `npm run deploy`
